# OpenCode V1/V2 Mobile (форк cfyz1297)

**Русский** | [English](README.md) · [llms.txt](llms.txt)

> **Android-клиент для AI-агента OpenCode.** Управляйте сессиями `opencode serve` с телефона: живой транскрипт, подтверждение инструментов, диффы, смена модели и уровня рассуждений — по локальной сети, Tailscale или через туннель. Работает с **opencode 1.x (V1 API) и 2.x (V2 API)**, версия определяется автоматически.

Форк [dzianisv/opencode-mobile](https://github.com/dzianisv/opencode-mobile), собран на Expo/React Native. Распространяется только как APK из GitHub Releases — без магазинов, без аккаунта и без собственного бэкенда: приложение общается напрямую с вашим сервером.

Репозиторий раньше назывался `opencode-mobile`, в 0.3.0 переименован в `opencode-v1-v2-mobile`. Старые ссылки перенаправляются, а имя файла APK (`opencode-mobile-v2.apk`) оставлено прежним: на него опираются встроенная проверка обновлений и цепочка проверки подписи релиза.

Версия **0.3.1 (66)**. Обновляется поверх 0.3.0 без удаления приложения.

> **Статус:** каждая сборка прогоняет 666 автотестов и Android CUA smoke на эмуляторе. Против настоящего сервера opencode 1.18.x ещё не проверялось; планшетный интерфейс, мастер туннелей и офлайн-история проверены в коде и на эмуляторе.

## Установка (Android, APK)

Стабильная ссылка — всегда последний релиз:

- **[Скачать opencode-mobile-v2.apk](https://github.com/cfyz1297/opencode-v1-v2-mobile/releases/latest/download/opencode-mobile-v2.apk)** (~86 МБ)

Файл APK по-прежнему называется `opencode-mobile-v2.apk`: на это имя опираются проверка подписи в CI и ссылка встроенной проверки обновлений, поэтому оно намеренно не менялось.

> ⚠️ Разовая переустановка: начиная с `0.2.9` APK подписывается постоянным ключом (раньше на каждый билд генерировался новый debug-ключ, поэтому обновление поверх не устанавливалось). Если стоит сборка старее — удалить её **один** раз и поставить текущую, дальше обновления ставятся поверх без удаления.

## Подключение к серверу opencode

Приложение говорит на **обоих поколениях API**: opencode 1.x (V1, его до сих пор ставит `npm install -g opencode-ai`) и opencode 2.0.x+ (V2, ставится нативным бинарником). При подключении адрес один раз опрашивается, ответ запоминается для этого подключения, и дальше используется подходящий транспорт — `/global/health` + `/global/event` для V1, `/api/info` + `/api/event` для V2. Определение идёт по телу и типу ответа, а не по коду: неизвестный маршрут на обоих поколениях проваливается в веб-интерфейс и отвечает `200 text/html` — именно поэтому клиент, знавший только V2, показывал «подключено» на V1-сервере и падал на первом же настоящем запросе.

Если автоопределение ошиблось, **Настройки → Сервер → API сервера** принудительно включает `v1` или `v2` для активного подключения.

Для V2:

1. Поставить и запустить сервер:

   ```bash
   curl -fsSL https://opencode.ai/v2/install | bash
   OPENCODE_SERVER_PASSWORD=вашпароль opencode serve --hostname 0.0.0.0 --port 4096
   ```
2. В приложении: **Add Connection** → адрес сервера (`http://IP:4096`), логин `opencode`, пароль из команды выше.

**На Android** сервер ставится из [opencode-termux](https://github.com/cfyz1297/opencode-termux): это OpenCode 2, собранный под Bionic, поэтому он работает прямо в Termux — без glibc, proot и слоёв совместимости.

```bash
curl -fsSL https://raw.githubusercontent.com/cfyz1297/opencode-termux/main/install.sh | bash
OPENCODE_SERVER_PASSWORD=вашпароль opencode serve --hostname 0.0.0.0 --port 4096
```

Обновление — `opencode upgrade` или повторный запуск команды установки. Сборки начиная с `2.2.5-r1` содержат исправление падения TUI на Android 17 (`Pointer exceeds safe integer range`); API сервера тот же, что у официального бинарника V2.

Формат V2 (проверено на 2.0.27): Basic-аутентификация только в виде `opencode:<пароль>` (Bearer и пустой пользователь = 401), все пути `/api/*`, страничные ответы `{data, cursor}`, SSE `GET /api/event`.

## Что умеет приложение

**Сессии и чат**
- Живой транскрипт: текст, рассуждения, вызовы инструментов, диффы и сводки компакции — в том порядке, в котором их выдала модель.
- Уточнение можно отправить, пока агент ещё работает: сервер ставит промпт в очередь.
- Кнопка «стоп» следует реальному статусу прогона на сервере, поэтому прервать можно и запуск, начатый не с этого экрана (приложение перезапускалось, другая сессия, открыли посреди работы).
- Редактирование сообщения с откатом сессии к нему (`revert` / `unrevert`), компакция истории в сводку.
- Запросы подтверждения инструментов и вопросы агента появляются прямо в диалоге; отвеченные вопросы остаются в переписке свёрнутой строкой.
- Неудачный прогон показывает причину от сервера вместо пустого пузыря.
- Размер страницы считается в промптах (5 / 10 / 25 / 50 / **Вся**). «Вся» загружает весь транскрипт.

**Информация о сессии**
- Кнопка в заголовке — кольцо, заполняемое по расходу контекста (синее, жёлтое после 50 %, красное после 80 %).
- В панели: токены, процент контекста с полоской, общая стоимость за всю сессию, модель и агент сессии.

**Модели и агенты**
- Пикер моделей с поиском, группировкой по провайдерам и отметкой активной модели.
- **Любимые модели**: звёздочка в любом пикере закрепляет модель в секции «Любимые» сверху; хранится только на устройстве и общее для всех подключений.
- Скрытые модели (экран «Модели») исчезают из обоих пикеров.
- Выбор уровня рассуждений (variant) для моделей, которые его поддерживают; шторки поднимаются вместе с клавиатурой, ни одна строка не остаётся под ней.

**Подключения и серверы**
- Несколько подключений: локальная сеть, Tailscale, туннель; пароли в Keystore/Keychain.
- **Поддержка V1 и V2** с автоопределением и ручным переключателем.
- Честный статус: «активно» значит, что сервер ответил; проверка при открытии вкладки, раз в 15 с и при возврате в приложение.
- Мастер туннелей для Cloudflare (именованные туннели) и ngrok.
- Экран провайдеров: подключение по API-ключу через сервер; в APK ключи не хранятся.
- Экран диагностики с копируемым отчётом (разбор URL, оба health-маршрута, определённое поколение API, доступность интернета).

**Надёжность и приватность**
- Восстановление после сбоев: watchdog потока, перечитывание переписки после тишины, `GET /api/session/active` для снятия «работает».
- Офлайн-история: шифрованная, только для чтения, с ограничениями.
- Телеметрии нет: Sentry и PostHog удалены.
- Биометрическая разблокировка, уведомления с фиксированным текстом (без присланных сервером имён инструментов и путей на экране блокировки).
- Планшетный интерфейс, любая ориентация, нативная подстройка под клавиатуру.

Основа — upstream [dzianisv/opencode-mobile](https://github.com/dzianisv/opencode-mobile) на теге `v0.4.15` (14.08.2026). Дальше у форка своя линия версий и свои задачи: один пользователь, один сервер в Termux, один канал доставки — APK.

| Версия | 0.4.x | линия 0.3.x, сейчас 0.3.1 (66) |

| Каналы | Google Play, self-hosted F-Droid, APK, EAS | только APK из GitHub Releases |
| Телеметрия | Sentry (краш-репорты) + PostHog | удалены обе зависимости |
| Языки | English, 简体中文 | + русский (en / ru / zh-Hans с проверкой паритета ключей) |
| Ориентация | только портрет | любая, планшетный расклад от 768 dp, две панели от 1000 dp |
| Офлайн-история | в планах | есть, шифруется Keystore/Keychain |
| Мастер туннелей | beta | Cloudflare (именованные туннели) и ngrok, встроенный мастер |
| Экран моделей | нет | есть: поиск, группы, видимость — влияет на оба окна выбора |
| Статус подключения | «выбрано» = «активно» | реальный ответ сервера, опрос при фокусе и раз в 15 с |
| Восстановление прогона | нет | сторож тишины, догрузка переписки, `GET /api/session/active` |
| Клавиатура | отступ в JS | нативный IME-инсет в `MainActivity` |
| Папка новой сессии | по умолчанию | выбранный проект (`location.directory` в теле запроса) |
| Тесты | `node --test` по glob | `scripts/run-tests.mjs` + порог покрытия 80 %, CUA smoke на эмуляторе |

Что изменено в коде:

- **Адаптер `src/lib/v2-compat.ts`**: ответы и события V2 приводятся к V1-форме, поэтому сторы и экраны остались прежними. V1-события (`session.status`, `message.part.updated`) собираются из V2-дельт (`session.text.delta`, `session.reasoning.delta`, `session.tool.*`).
- **SDK** переключён на `/api/session`, `/api/event`, `/api/info`, `/api/permission/request`, `/api/fs/*`, `/api/project`, `/api/location`. Смена модели/агента сессии — через `POST /api/session/{id}/model` и `/agent`.
- **Транспорт V1** (`src/lib/sdk-v1.ts`, `src/lib/api-detect.ts`): то же приложение работает с сервером opencode 1.x — `/session`, `/experimental/session`, `/session/{id}/prompt_async`, `/global/event`. Определённый API хранится в подключении (`api`, `serverVersion`) и сбрасывается при смене URL. Взято из upstream PR #209 / релиза v0.4.16.
- **Карточки инструментов** (`src/lib/tool-view.ts`): инструмент `shell` (имя в 2.x) показывается как терминал с командой, выводится заголовок прогресса из `session.tool.progress`, а пустой вывод откатывается к входным данным вместо пустой карточки.
- **Новые экраны и логика**: `app/history.tsx` (офлайн-история), `app/models.tsx` (видимость моделей), `app/providers/*` (каталог и подключение провайдера ключом через сервер), `app/connection/tunnel.tsx` (мастер туннелей), `src/components/TabletSessions.tsx` (планшет), `src/lib/adaptive-layout.ts`, `src/lib/connection-health.ts`, `src/lib/connection-security.ts`, `src/lib/run-watchdog.ts`, `src/lib/stream-watchdog.ts`, `src/lib/keyboard-inset.ts`, `src/lib/message-page.ts` (страница в промптах, `ALL_TURNS`, `keepLoadedHistory`), `src/lib/session-stats.ts`, `src/lib/tool-view.ts`, `src/lib/api-detect.ts`, `src/stores/model-favorites.ts`.
- **V2-специфика**: вопросы агента идут через формы V2, в переписке видны саммари компакции, вложения-картинки рендерятся как изображения, чат следует за потоком, композер очищается после встроенной команды.
- **Изоляция клиентов**: SDK-клиент привязан к подключению, поэтому потоковые сообщения и выбранная модель не перетекают между серверами.
- **Удалено вместе с инфраструктурой**: `website/`, `docs-site/`, `fastlane/`, `fdroid/`, `distribution/`, `eas.json`, `.maestro/`, `.autopilot/`, `.supervisor/`, `.tasks/`, workflow сборки iOS и публикации в магазины, Sentry-плагин и source-map upload.
- **Безопасность**: заблокировано разрешение `SYSTEM_ALERT_WINDOW`, пароли и офлайн-копии пишутся с политикой `WHEN_UNLOCKED_THIS_DEVICE_ONLY`, форма подключения предупреждает о пароле по незашифрованному `http://`. Уведомления о подтверждении инструмента и о вопросе агента содержат фиксированный текст, а не присланные сервером имена инструментов, пути и текст вопроса: шторка уведомлений читается с заблокированного экрана (аудит upstream M-03, перенесено). Запросы несут `ngrok-skip-browser-warning` и `Bypass-Tunnel-Reminder`, чтобы туннель проксировал API, а не отдавал свою страницу-заглушку.

Чего в форке нет (сознательно или пока): OAuth-подключения провайдеров (только API-ключ), OpenCode Cloud (только лист ожидания), iOS-сборки, магазинов и телеметрии.

## Что осталось от оригинала

Демо-режим без сервера, мультиподключения (LAN, туннель, Tailscale), биометрическая разблокировка, потоковый чат, дифф-вьюер, подтверждение вызовов инструментов, вопросы агента, безопасное хранение паролей, уведомления, баннер о новой версии. Подробнее — [upstream README](https://github.com/dzianisv/opencode-mobile#readme).

## Безопасность

- Пароли серверов и офлайн-история лежат в Android Keystore / iOS Keychain с политикой `WHEN_UNLOCKED_THIS_DEVICE_ONLY`: они не попадают в резервные копии ОС и не восстанавливаются на другом устройстве.
- Обычный `http://` не шифрует ни пароль, ни переписку. Формы подключения предупреждают об этом; для недоверенных сетей используйте https, туннель или Tailscale. Loopback (Termux на том же телефоне) предупреждения не показывает — трафик не покидает устройство.
- Приложение не запрашивает `SYSTEM_ALERT_WINDOW` (рисование поверх других приложений).
- Зависимости сборки: `npm audit` показывает 34 записи (7 high) в цепочке Metro/PostCSS/Expo CLI. `npm audit fix --force` откатывает Expo до 51 и ломает проект. В поставляемый APK этот код не входит — он исполняется только при сборке на CI.

## Мастер Cloudflare / ngrok

Для Cloudflare нужен **именованный туннель**, аккаунт и домен: в панели Cloudflare создайте Tunnel и Published application route с Service URL `http://127.0.0.1:4096`, затем запустите команду с токеном на компьютере. Токен Cloudflare в приложение не вводится. Быстрые адреса `trycloudflare.com` отклоняются мастером: [они не поддерживают SSE](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/#limitations), необходимый для потоковых ответов. Альтернатива без своего домена — ngrok. Установку cloudflared/ngrok и вход в ngrok выполняет владелец компьютера.

## Сборка из исходников

```bash
git clone https://github.com/cfyz1297/opencode-v1-v2-mobile
cd opencode-mobile
npm install
npm run android            # dev-сборка на устройстве/эмуляторе
```

Релизный APK собирает GitHub Actions (`.github/workflows/build.yml`) на каждый push в `main` и на теги `v*`: сначала тесты, typecheck и проверка версий, потом `expo prebuild` + `gradlew assembleRelease`. Артефакт — `app-release`; GitHub-релиз с APK публикуется вручную.

Тесты (Node.js 24+): `npm test`. Общее покрытие с порогом 80 %: `npm run test:coverage`. Typecheck: `npm run typecheck`. Версии в `package.json`, `app.json` и `android/app/build.gradle`: `npm run check:versions`.

Сборка включает Android CUA smoke: релизный APK, команды мастера, отклонение HTTP до сетевого обращения, переходы между сессиями в двух панелях, смена размера окна, холодный перезапуск без сервера, чтение и очистка истории. Артефакт `roadmap-smoke-evidence` содержит снимки экрана и результат.

Проверка безопасности и обоснование исправлений: [docs/security-review-0.2.21.md](docs/security-review-0.2.21.md), статус подключения: [docs/connection-status-validation.md](docs/connection-status-validation.md), видимость моделей: [docs/model-visibility-validation.md](docs/model-visibility-validation.md), восстановление прогона: [docs/run-resync-validation.md](docs/run-resync-validation.md). Текущее состояние проекта и порядок релиза: [HANDOFF.md](HANDOFF.md).

Отдельный клиент на чистом Java без Gradle (`aapt → ecj → d8 → apksigner`), тоже на V2 API, живёт в другом репозитории.

## Обновления

<details>
<summary>Список изменений по версиям (0.2.11 – 0.3.1)</summary>

### 0.3.1

- **Нет краша при выходе из сессии во время стрима.** Заголовок экрана сессии заново регистрировал нативные опции на каждой порции потока, поэтому выход из экрана, пока прогон печатал ответ, мог разобрать экран посреди этого обновления (`react-native-screens`, «child already has a parent»). Теперь опции применяются через `navigation.setOptions` в эффекте, который срабатывает только при изменении видимых данных заголовка — названия, бейджа папки, процента кольца, темы. Порт из апстрима v0.4.17.

### 0.3.0

- **Работает с opencode 1.x и 2.x.** Второй транспорт (`src/lib/sdk-v1.ts`) закрывает V1 API — `/session`, `/experimental/session`, `/session/{id}/prompt_async`, `/global/event`, права, вопросы, файлы, агенты, команды, провайдеры. Адрес один раз опрашивается на подключение, ответ запоминается; определение идёт по телу и типу ответа, а не по коду, потому что неизвестный маршрут на обоих поколениях проваливается в веб-интерфейс и отвечает `200 text/html`. **Настройки → Сервер → API сервера** принудительно включает `v1` или `v2` (сразу, без перезапуска). События, которые присылает только 1.18.x (`session.idle`, `permission.updated`, `permission.v2.*`), нормализуются — иначе запрос подтверждения не появился бы, а прогон висел бы вечно.
- **Любимые модели.** Звёздочка в строке закрепляет модель в секции «Любимые» сверху обоих пикеров. Хранится на устройстве (только id провайдера и модели), общее для всех подключений; любимая модель остаётся и в списке провайдера, скрытая — остаётся скрытой.
- **Карточки инструментов больше не пустые.** Три причины: заголовок прогресса из `session.tool.progress` принимался и выбрасывался, пустая строка вывода скрывала входные данные, а имя `shell` в 2.x не распознавалось (был только `bash`) — не было ни иконки терминала, ни команды. Решение вынесено в `src/lib/tool-view.ts` и покрыто тестами.
- **Кольцо контекста и стоимость сессии.** Кнопка в заголовке стала кольцом, заполняемым по расходу контекста, а панель показывает стоимость всей сессии рядом с процентом. Стоимость раньше суммировалась по загруженным сообщениям и занижалась для длинной сессии; теперь предпочитается накопленное сервером `session.cost`.
- **Чат больше не теряет сообщения по ходу.** «Загрузить старые» сбрасывал `hasMore` после загрузки, а каждое следующее обновление экрана (фокус, возврат из фона, реконнект) заменяло переписку страницей, обрезанной до настройки, — сообщения исчезали до перезахода. Теперь старые сообщения сохраняются, если полная история уже известна.
- **«Загрузить старые» действительно грузит всё.** Запрос шёл без `limit`, сервер отдавал свои 50 сообщений по умолчанию, и стор помечал историю загруженной — всё старше становилось недоступным. Теперь запрашивается максимальная страница (200) и обход идёт по курсору сообщений, пока он приносит новые строки.
- **Кнопка «стоп» есть всегда во время прогона.** Раньше она зависела от локального флага «я отправил», поэтому запуск, начатый не с этого экрана, прервать было нельзя — долгую сборку нечем было остановить.
- **Кнопки вложения и вставки не могут молча не сработать.** Необработанные промисы пикера и буфера обмена перехватываются и показываются пользователю; пикер закрывает клавиатуру и игнорирует повторный запуск, пока открыт.
- **Выбор уровня рассуждений при открытой клавиатуре.** Шторка оставалась за клавиатурой и последняя строка была недоступна; теперь клавиатура закрывается, а шторка поднимается вместе с ней, как у выбора модели.
- **Список сессий больше не обрезан.** V2-транспорт не читал курсор ответа (сервер по умолчанию отдаёт 50), V1 — заголовок `x-next-cursor` (100), поэтому сессии, видимые в TUI, отсутствовали в приложении. Теперь оба обходят курсор, с ограничением и дедупликацией.
- **Туннели работают.** Запросы несут `ngrok-skip-browser-warning` и `Bypass-Tunnel-Reminder`; без них ngrok отвечал своей страницей, а приложение сообщало о неверном пароле.
- **В уведомлениях нет серверного текста.** Уведомления о подтверждении и о вопросе — фиксированные строки: шторка читается с заблокированного телефона, а детали (имена инструментов, пути, команды) присылает сервер.
- **Репозиторий переименован** в `opencode-v1-v2-mobile`.

### 0.2.30

- **Неудачный прогон теперь объясняет причину.** Когда прогон падает — например, бесплатная модель отвечает `429 Free usage limit reached` — сервер записывает причину в assistant-сообщение и не присылает текст ответа. Чат рисовал пузырь без содержимого, поэтому сессия, которая на самом деле падала с ошибкой, выглядела зависшей и переставшей отвечать. Теперь причина показывается в пузыре красным, ровно там, где был бы ответ, и остаётся видимой после перезахода в сессию — она берётся из переписки.

### 0.2.29

- **Уточнение можно отправить, пока агент ещё работает.** Композер не отправлял сообщение до конца прогона, и добавить мысль по ходу можно было только дождавшись ответа. Теперь блокируется лишь отправка, которая уже в пути; сервер, как и раньше, ставит следующий запрос в очередь.
- **Отвеченные вопросы остаются в диалоге.** Карточка вопроса пропадала сразу после того, как сервер принимал ответ, и единственным напоминанием оставался двухсекундный отклик. Теперь она остаётся на месте вопроса — свёрнутая в одну строку, а по нажатию раскрывается со списком вариантов и отмеченными ответами.
- **«Сообщений на странице» теперь считает запросы, а не сообщения.** На один запрос агент обычно выдаёт десятки записей (шаг на каждый вызов инструмента), поэтому настройка выглядела нерабочей — 50 «сообщений» часто были одним обращением. Теперь страница измеряется вашими запросами и всегда начинается с одного из них. Сессии, открытые до этой версии, получают значение по умолчанию: старые числа несопоставимы.

### 0.2.28

- **Вернулась стоимость сообщения на серверах 2.2.5 и новее.** Сервер теперь передаёт присланную провайдером сумму как есть, а `opencode-go` присылает ноль, поэтому футеру нечего было показать и строка стоимости пропадала целиком. Если цена от сервера нулевая, приложение считает её по каталогу модели — input, output, размышления и кэш, той же формулой, что и сервер.
- **Чат больше не зависает после долгого сворачивания приложения.** Пока приложение было в фоне, поток событий копился; при возврате весь бэклог применялся разом, и каждое обновление заново перерисовывало и разбирало markdown всего сообщения — поток JS не успевал отдать управление, и тапы с навигацией не работали до конца прогона. Теперь обновления частей склеиваются, а поток уступает управление после каждого чанка.

### 0.2.27

- **Инструменты и мысли в чате идут в том же порядке, что и на компьютере.** Раньше ответ агента выглядел как «стена размышлений сверху, все вызовы инструментов внизу»: промежуточные реплики модели между шагами терялись в общей куче, а строка «Выполнено команд: N» повторялась на каждом шаге. Теперь каждый шаг показывает свои размышления, свою строку инструментов и свой текст в том порядке, в котором их выдала модель: запрос → мысли → инструменты → «Now the plan: …» → снова инструменты → окончательный ответ. Шапка «Assistant + модель» одна на весь прогон.
- **В конце — стоимость всего прогона, а не последнего шага.** Футер показывал токены и деньги только последнего roundtrip, из-за чего длинный прогон выглядел в разы дешевле, чем был. Теперь суммируются все шаги от вашего сообщения до конца ответа.
- **Метки команд снова совпадают с сервером.** `isCommandRun` и детали вызова знали только `bash`, а V2 называет инструмент `shell`: реальные запуски получали метку «Выполнено инструментов» с иконкой пазла и теряли командное превью. Исправлено.
- **Убрана привязка к Google Play.** Приложение не публикуется в магазинах, поэтому запрос оценки через Play In-App Review (`expo-store-review`) удалён вместе с зависимостью, счётчиком сессий в SecureStore и политикой порога. В APK больше нет кода магазина.

### 0.2.26

- **Возвращён правильный вид чата.** В 0.2.25 блок вопросов занял половину экрана, и сообщения уезжали вверх с пустой полосой над полем ввода: у `ScrollView` в React Native `flexGrow: 1` по умолчанию, поэтому даже пустой блок тянулся вверх. Теперь он не растёт, а сжимается только когда карточка не влезает. Закреплено тестом.

### 0.2.25

- **Ввод текста больше не уезжает за клавиатуру.** При открытой клавиатуре всё окно приложения теперь сжимается под неё нативно (раньше под клавиатуру подстраивался только внутренний блок, поэтому нижняя часть экрана — вместе со строкой ввода — оставалась под ней). Дополнительно блок вопросов с вариантами ответа стал прокручиваемым: раньше при висящих вопросах он выталкивал строку ввода за пределы экрана, и написать в чат было нельзя, не закрыв клавиатуру. Теперь строка ввода видна всегда, а варианты ответа прокручиваются в оставшемся месте. Покрыто тестами.

### 0.2.24

- **Новая сессия создаётся в выбранном проекте, а не в домашней папке сервера.** При выборе проекта (в списке недавних, среди проектов сервера, в обзоре папок или через переключатель проекта) сессия действительно открывается в этой папке. Раньше сервер V2 игнорировал заголовок с папкой при создании сессии и складывал все новые сессии в свой рабочий каталог — обычно `~`. Теперь папка передаётся в теле запроса (`location.directory`); покрыто HTTP-тестом SDK.
- **Поле ввода больше не прячется за клавиатурой.** При наборе ответа клавиатура перекрывала строку ввода: приложение поднимало интерфейс всего на высоту системной панели навигации вместо высоты клавиатуры (ошибка в расчёте высоты, а не в самой клавиатуре). Теперь отступ берётся из системного отступа клавиатуры; исправление общее для всех экранов с вводом — чат, новая сессия, подключения. Покрыто тестом расчёта.

### 0.2.23

- **Сессия оживает после пропадания сети.** Если прогон на сервере закончился (или оборвался) пока телефон был без сети, приложение теперь спрашивает сервер, что он реально выполняет, и снимает «Работаю…»: сессия снова принимает сообщения, а прошлая работа показывается. Раньше в этом случае спиннер и блокировка поля ввода оставались навсегда — помогала только перезагрузка приложения.

### 0.2.22

- **Ответ больше не «прячется» до перезахода в сессию.** Если события одного прогона потерялись, а сокет жив, приложение теперь само дочитывает переписку через 12 секунд тишины: ответ появляется на экране, «Работаю…» гаснет, а если модель всё ещё работает — подтягивается уже написанная часть. Раньше помогал только выход из сессии и обратно.

### 0.2.21

Проверка идёт при открытии вкладки, раз в 15 с и при возврате приложения на передний план; результат привязан к серверу, поэтому ответ старого подключения не красит новое.

## Коротко о проекте (для тех, кто просматривает, и для ИИ-агентов)

- **Что это:** нативный Android-клиент (Expo / React Native, TypeScript) к [opencode](https://github.com/sst/opencode) — открытому AI-агенту для программирования.
- **Что это не:** не модель, не хостинг, не бэкенд. Своего сервера нет; промпты, код и креденшелы не покидают устройство никуда, кроме вашего же сервера.
- **Архитектура:** устройство общается напрямую с `opencode serve` по HTTPS с Basic-авторизацией. Два транспорта: V2 (`/api/*`, opencode 2.x) и V1 (`/session`, `/global/*`, opencode 1.x). Выбор определяется при подключении (`src/lib/api-detect.ts`) и может быть включён принудительно в настройках.
- **Как получить:** APK из [Releases](https://github.com/cfyz1297/opencode-v1-v2-mobile/releases/latest); ставится поверх предыдущих версий, подписан постоянным ключом.
- **Как запустить:** поднять `opencode serve` в доступном месте, ввести адрес в приложении. Локальная сеть, Tailscale, Cloudflare Tunnel и ngrok — работают все.
- **Требования:** Android 7+ (minSdk 24), сервер opencode 1.18+ или 2.x, сетевой доступ к нему.
- **Структура кода:** `app/` (экраны Expo Router), `src/lib` (SDK, транспорты, чистые хелперы — почти всё покрыто юнит-тестами), `src/stores` (zustand), `src/components` (UI). `HANDOFF.md` — рабочий инженерный журнал, `docs/` — разбор апстрима и отчёт по безопасности.
- **Проверки:** `npm test` (666 тестов, встроенный раннер node), `npm run typecheck`, `npm run check:versions`, `npm run test:coverage` (≈98 % строк).
- **Машиночитаемая сводка:** [`llms.txt`](llms.txt).
- **Лицензия:** MIT (унаследована от оригинала).
