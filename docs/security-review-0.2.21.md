# Проверка безопасности 0.2.21

Дата: 2026-10-25. Ветка `feat/providers-model-picker`. Отчёт по статусу подключения: `docs/connection-status-validation.md`.

Проверялось: новый код 0.2.21 (статус подключения, экраны подключения, хранилище паролей), поверхность атаки релизного APK и зависимости сборки. Метод: чтение кода и диффа, `security-review`, `npm audit --omit=dev`, разбор манифеста собранного APK, автотесты-инварианты.

## Исправлено

## Проверено, изменений не потребовалось

- Аутентификация: Basic `opencode:<пароль>` собирается в `src/lib/auth.ts` и уходит только на сохранённый `baseUrl`; новых адресов и способов аутентификации в 0.2.21 нет. Health-проверка использует тот же клиент.
- Новых разрешений, схем глубоких ссылок, WebView, динамического исполнения кода и хранилищ не добавлено. Схема `opencode://` не обрабатывает URL подключений, поэтому подсунуть сервер ссылкой нельзя.
- Ответы сервера в UI: только фиксированные ключи переводов, без HTML и без вставки текста сервера (в т.ч. в новом бейдже статуса). Ответ health не логируется.
- Логи: ни пароли, ни заголовок `Authorization`, ни токены в `console.*` не попадают.
- Fail-closed: статус «Активно» требует явного `healthy === true`, любой сбой/не-2xx/не-JSON → «Сервер недоступен».
- Резервное копирование Android: `allowBackup=true`, но элементы SecureStore исключены правилами `secure_store_*`; в AsyncStorage остаются только очередь письма waitlist и состояние проверки обновлений.
- Пути к файлам и `/api/fs/*` — существующая функциональность, в 0.2.21 не менялась.

## Известные остатки (приняты)

- **Пароль по http.** Предупреждение, а не запрет: приложение изначально работает с самодельными серверами по LAN, где https часто нет. Решение остаётся за пользователем.
- **`usesCleartextTraffic=true`** нужен для тех же LAN-серверов; ограничить его списком хостов нельзя, серверов произвольно много.
- **`npm audit`: 11 уязвимостей (7 high)** в цепочке сборки Metro/PostCSS/Espree/`@expo/code-signing-certificates`. `npm audit fix --force` откатывает Expo до 44 и ломает проект. В APK этот код не попадает: он исполняется только при сборке на CI; риск — компрометация сборочного раннера, а не устройства пользователя.
- **401/403** в бейдже статуса показывается как «Сервер недоступен» (fail-closed), без отдельной подсказки про пароль; сообщение об ошибке авторизации по-прежнему показывает экран сессий.

Не проверялось: физическое устройство (кроме Android CUA smoke на эмуляторе), полный аудит сторонних зависимостей, iOS-сборка, серверная часть `opencode serve` (вне репозитория).
