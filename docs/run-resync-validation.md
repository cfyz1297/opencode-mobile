# Обновление диалога без перезахода в сессию (0.2.22)

Дата: 2026-10-25. Ветка `main`. Предыдущие отчёты: `docs/connection-status-validation.md`, `docs/security-review-0.2.21.md`.

## Симптом

Пользователь отправляет сообщение, ждёт ответа, но в чате остаётся пустой блок Assistant и «Работаю…». Ответ при этом уже есть на сервере: после выхода из сессии и повторного входа вся переписка отображается. Кнопка Stop видна, баннера переподключения нет, то есть SSE-соединение живое.

## Причины

1. Идущий прогон обновляет интерфейс только через события SSE. Если события именно этой сессии не дошли (потерянный чанк, переход статуса, который приложение не увидело, разрыв во время переподключения), локальное состояние остаётся «busy».
2. Единственный сторож (`src/lib/stream-watchdog.ts`) следит за **всем сокетом**. Сервер шлёт `: heartbeat` каждые ~15 с, поэтому `lastStreamActivityAt` свежий, `isStreamStalled` никогда не срабатывает — потеря событий одной сессии для него невидима.
3. Пересинхронизация выполнялась только на переподключении и при входе в сессию (`useFocusEffect` → `selectSession`), что и объясняет «помогает перезаход».

## Исправление

- `src/lib/run-watchdog.ts` — чистая функция `runsNeedingResync`: по каждой **сессии** отдельно, тишина ≥ `RUN_QUIET_MS` (12 с) означает, что клиент отстал; не чаще одной проверки на окно тишины.
- `src/stores/events.ts`:
  - часы `sessionActivityAt` / `sessionResyncedAt` на каждую сессию; обновляются любым событием этой сессии (`session.status`, `message.updated`, `message.part.updated`, `session.error`);
  - в существующий сторож (каждые 5 с) добавлена проверка «тихих» прогонов: для каждой такой сессии — `GET` переписки уже авторизованным клиентом;
  - сервер подтвердил завершение (`isSessionActuallyIdle`) → прогон закрывается локально, переписка применяется сразу;
  - сервер ещё работает → применяется уже полученная переписка, статус остаётся busy (виден частичный ответ);
  - `finishRunLocally` удаляет часы сессии, чтобы следующий запуск не выглядел «молчащим» с первой секунды;
  - 404 (сессию удалили в другом месте) закрывает прогон, чтобы не опрашивать его вечно.
- `src/stores/sessions.ts` — `applyServerMessages(response)`: применить уже загруженную переписку без второго GET, с тем же согласованием оптимистичных сообщений (`reconcileTemps`).

## Проверка безопасности

Фокусный ревью диффа (независимый агент + `security-review`), замечания исправлены:

| Severity | Замечание | Исправление |
|---|---|---|
| MED | После восстановления по таймауту в картах оставались старые метки времени: следующий запуск выглядел «молчащим» сразу и мог быть закрыт по чужому завершению | `finishRunLocally` удаляет часы сессии; тест `a recovered run does not fast-forward the next one` |
| LOW | Удалённая сессия опрашивалась бы вечно (1 запрос / 12 с) | 404 закрывает прогон; тест `a session deleted elsewhere stops being polled` |
| LOW | Двойной GET переписки на окно (проверка + отображение) | `applyServerMessages` применяет уже полученный ответ; тест проверяет ровно один вызов |

Проверено, изменений не потребовалось:

- Новых адресов, ключей, разрешений, хранилищ и логирования секретов нет: используется тот же авторизованный клиент и сохранённый `baseUrl`; в лог попадают только идентификаторы сессий, как и раньше.
- Доверие: локальное состояние только **сбрасывается** по данным сервера; тот же сервер и так управляет статусом через SSE, новых возможностей не появляется. Ничего не отправляется и не удаляется на сервере.
- Ресурсы: не более одного `GET /session/{id}/message` на 12 с на активную сессию (плюс транспортный таймаут 30 с), проверка только пока приложение считает прогон активным.
- Жизненный цикл: интервал и слушатели снимаются в `finally`, работа прекращается по `signal.aborted`, карты очищаются в `disconnect()`.

Остаток (принят): если сессия навсегда остаётся «busy», а сервер отвечает не-404 ошибкой, опрос продолжится с шагом 12 с. Ограничение по времени жизни не добавлено намеренно — иначе можно потерять настоящий долгий прогон.

Не проверялось: поведение на физическом устройстве (в CI был эмулятор), реальные серверы с паузами в событиях дольше 12 с, фоновая работа таймеров под Doze.
