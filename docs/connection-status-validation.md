# Connection status: validation and security review

Дата: 2026-10-25. Ветка `feat/providers-model-picker`. Предыдущая задача: `docs/model-visibility-validation.md`.

## Проблема

На экране «Подключения» активное подключение было зелёным с бейджем «Активно», даже когда `opencode serve` в Termux остановлен. Причина: `isActive` — это сохранённый выбор подключения (`connection.active`), а не результат проверки сети. Health-check на экране отсутствовал.

## Исправление

- `src/lib/connection-health.ts` — `probeConnection(client, timeoutMs = 5000)`: вызывает существующий авторизованный `client.global.health()`; `online` только при явном `healthy === true`, любой throw/не-2xx/иное значение → `offline` (fail-closed).
- `app/(tabs)/connections.tsx`:
  - бейдж и зелёная подсветка зависят от реального статуса: «Активно» / «Сервер недоступен» / «Проверка...»; иконка красная при недоступности;
  - проверка при фокусе вкладки (`useFocusEffect`), раз в 15 с и при возврате приложения на передний план; всё снимается при уходе с вкладки;
  - в полёте одна проверка, результат привязан к клиенту: поздний ответ старого сервера не перекрашивает новый;
  - ключи переводов `connectionsList.offlineBadge` и `connectionsList.checkingBadge` в en/ru/zh-Hans.

## Проверка безопасности (focused review)

Применены `security-review` и `security-audit` (focused source review) + независимый агент по диффу.

Проверено:

- Новых сетевых адресов, credential-ов, разрешений, хранилищ, логов и динамического исполнения нет: проверка использует уже созданный клиент с сохранённым `baseUrl` и Basic auth из store; ответ сервера никуда не сохраняется.
- Ответ сервера не попадает в UI и логи: рендерятся только фиксированные ключи переводов, никакого HTML/команд.
- Fail-closed: throw, не-2xx, не-JSON, отсутствующий или не-булев `healthy` → «недоступен». Подделать зелёный статус ответом нельзя.
- Жизненный цикл ограничен: один интервал и один `AppState`-слушатель на запуск эффекта, оба снимаются при уходе с вкладки; таймаут проверки 5 с; параллельные проверки не накладываются.
- Загрузка на сервер: один `GET /api/info` раз в 15 с только при открытой вкладке.

Остаточные риски (приняты, не исправлялись):

- `client.global.health()` в `src/lib/sdk.ts` трактует отсутствующий `healthy` как `true` для совместимости со старыми серверами. Поэтому сторонний сервис, отвечающий 200 JSON на `/api/info`, может показать «Активно». Это только индикатор: остальные запросы к такому серверу всё равно упадут.
- 401/403 отображается как «Сервер недоступен» (fail-closed), но не подсказывает про неверный пароль; сообщение об auth-ошибке по-прежнему показывает экран сессий.

Не проверялось: реальное устройство/эмулятор с выключенным Termux (проверка на APK — следующий шаг), поведение фокуса `expo-router` на устройстве, полный аудит остального auth-кода и зависимостей (вне этой задачи).
