# Проверка безопасности: V1, пикер моделей, карточки инструментов

Дата: 2026-11-04. Ветка `feat/server-api-v1`. Предыдущий отчёт: `docs/security-review-0.2.21.md`.

Проверялось: транспорт V1 (`src/lib/sdk-v1.ts`), определение API (`src/lib/api-detect.ts`), хранение выбранной версии, заголовки запросов, диагностика, тексты уведомлений, любимые модели (`src/lib/model-visibility.ts`, `src/stores/model-favorites.ts`), карточки инструментов (`src/lib/tool-view.ts`, `ToolCallCard.tsx`). Метод: чтение нового кода и диффа, `npm audit`, инварианты в тестах, ручная проверка поверхностей (заголовки, логи, SecureStore, манифест).

## Что изменилось после первого прогона

- Уведомления о подтверждении/вопросе — фиксированный текст (п.1).
- Health-проба больше не считает HTML-страницу живым сервером (п.2). Туннельные заголовки (п.3).
- Парсинг списка сессий: транспорт читает `cursor`/`x-next-cursor` и дедуплицирует по id; повторный или нечисловой курсор завершает обход, поэтому сервер не может удержать клиент в бесконечном цикле запросов. Адреса запросов не меняются (тот же `baseUrl`).

## Проверено, изменений не потребовалось (дополнение)

- **Любимые модели.** Звёздочка — только локальная настройка: никуда не отправляется, в API моделей не пишется, на выбор модели не влияет. Скрытые модели остаются скрытыми даже если помечены любимыми (тест `model-picker-filter`).
- **Отрисовка карточек инструментов.** Текст вывода/ввода рендерится как `Text`, а не как HTML/markdown; серверный `JSON.stringify` не исполняется. Заголовок ограничен `numberOfLines={1}`, поэтому многострочный заголовок от сервера не может раздвинуть интерфейс.
- **Новых сетевых поверхностей нет:** обе правки локальные (UI + хранилище), заголовки и адреса не менялись.

## Проверено, изменений не потребовалось

- **Куда уходят данные.** Проба и V1-клиент обращаются только к `baseUrl` подключения: `probeServer` шлёт Basic-заголовок на `/api/info` и `/global/health` того же хоста, третьих адресов и аналитики нет. Ключ провайдера (`provider.connectApiKey`) на V1 уходит на `/auth/{id}` того же сервера и нигде не сохраняется на телефоне.
- **Секреты.** Пароли по-прежнему пишутся только с `WHEN_UNLOCKED_THIS_DEVICE_ONLY`; выбранная версия API — не секрет и хранится рядом с остальными настройками. В логи не попадают ни `Authorization`, ни тело промптов; парсер SSE логирует только длину нечитаемого события.
- **Fail-closed.** Неизвестный сервер (HTML на обоих маршрутах, сеть, таймаут) → подключение не создаётся. Принудительно выбранная неверная версия даёт не-JSON ответ или 404 → `ApiError` и «сервер недоступен», а не тихий успех.
- **Новый экран настроек.** Переключатель меняет только транспорт; он не принимает URL, не подставляет прокси и не расширяет поверхность атаки. Deep link `opencode://` версию по-прежнему не задаёт.
- **Инъекция в UI.** Тексты в настройках — фиксированные ключи переводов (en/ru/zh-Hans, паритет проверяется тестом). Ответы сервера разметкой не рендерятся.
- **Манифест APK.** Новых разрешений нет: `SYSTEM_ALERT_WINDOW` остаётся заблокированным через `expo.android.blockedPermissions` (проверяется `security-baseline.test.ts`), `usesCleartextTraffic` не менялся.
- **Совместимость не расширяет доверие.** V1-сервер получает те же Basic-креденшелы, что и V2; отдельного «доверенного» или анонимного режима не появилось.

## Известные остатки (приняты)

- **`npm audit`: 34 записи (7 high)** — все в цепочке сборки/тулинга (Metro, PostCSS, `@expo/config`, `node-forge`, `decode-uri-component` через `expo-router`, `brace-expansion`). `npm audit fix --force` откатывает Expo до 51 и ломает проект. В APK этот код не исполняется: риск — компрометация сборочного раннера, а не устройства.
- **Текст уведомления о завершении/ошибке** по-прежнему содержит заголовок сессии или сообщение сервера. Это осознанно: полезность push без него нулевая, а содержимое ограничено пользовательской перепиской. Permission/question вынесены в фиксированный текст, потому что там серверный текст — это имена инструментов и пути.
- **Пароль по `http://`** остаётся предупреждением, не запретом: самодельные серверы в LAN часто без TLS.
- **V1 не отдаёт `/api/session/active`.** Для V1-подключений остаётся эвристика по переписке; вечный «busy» теоретически возможен, как и раньше на серверах V2 старше 2.0.24.

Не проверялось: реальное устройство (установка и работа переключателя вручную), живой V1-сервер 1.18.x (контракт закреплён HTTP-тестами против локального сервера, но не против настоящего `opencode serve` 1.18), iOS-сборка.
