Актуально на **2026-11-04**.

## Не выпущено (ветка `feat/server-api-v1`, 2026-11-04)

- **Совместимость с opencode 1.x (V1 API).** Новый транспорт `src/lib/sdk-v1.ts` (порт upstream PR #209 / релиза v0.4.16): `/session`, `/experimental/session`, `/session/{id}/prompt_async`, `/global/event`, `/permission/*`, `/question/*`, `/file*`, `/path`, `/agent`, `/command`, `/provider`, `/config`. Модель/агент в V1 едут в теле промпта — отдельных `POST /session/{id}/model|agent` там нет. Ответы V1 отдаются в той же форме, что и адаптированные V2, поэтому сторы и экраны не менялись. События `session.idle`, `permission.updated` и `permission.v2.*` (их шлёт сервер 1.18.x) нормализуются в те имена, которые уже знает `src/stores/events.ts`.
- **Определение версии сервера.** `src/lib/api-detect.ts`: `GET /api/info` (JSON или 401/403 → V2), иначе `GET /global/health` (JSON или 401/403 → V1); HTML на обоих маршрутах = это не сервер opencode. Решение принимается по типу ответа, а не по коду, потому что неизвестный маршрут на обоих поколениях отдаёт `200 text/html` из веб-интерфейса. Результат пишется в подключение (`api`, `serverVersion`) и сбрасывается при смене URL; ошибка пробы оставляет прежнее поведение (V2), чтобы сохранённое подключение не переставало открываться.
- **Переключатель «Настройки → Сервер → API сервера»** (`auto` / `v1` / `v2`). `auto` — определение и запоминание; принудительное значение обходит пробу и применяется сразу (клиент и SSE пересоздаются), чтобы можно было обойти проблему сервера. Настройка хранится вместе с остальными (`settings.serverApi`), при загрузке неизвестное значение падает в `auto`.
- **Туннели.** Запросы несут `ngrok-skip-browser-warning` и `Bypass-Tunnel-Reminder` (upstream #219): иначе ngrok отдаёт свою страницу-заглушку вместо API, и приложение сообщало «неверный пароль».
- **Уведомления без серверного текста.** Запрос подтверждения и вопрос агента больше не выносят в шторку имя инструмента, пути, команду и текст вопроса (аудит upstream M-03): только фиксированные строки, детали — в приложении.
- **Диагностика.** Health-проба успешна только при JSON или 401/403 (`requireJson` + `chooseHealthProbe` в `src/lib/diagnostics.ts`, `diagnostics-classify.ts`), поэтому HTML-заглушка больше не читается как «соединение работает». В отчёт добавлена строка `Server API: v1|v2`.
- Тесты: `src/lib/api-detect.test.ts` (6), `src/lib/sdk-v1.integration.test.ts` (15, настоящий HTTP-сервер), плюс расширены `connection-bootstrap`, `diagnostics-classify`, `settings-persistence`, `headers`, `notify-format`.
- Отчёт безопасности: `docs/security-review-server-api.md`.

### Исправления по отчётам с устройства (та же ветка)

- **История чата больше не пропадает.** `loadOlderMessages()` выставляет `hasMore=false`, но каждое обновление экрана (фокус, возврат из фона, реконнект) заменяло переписку страницей, обрезанной до значения настройки, — сообщения исчезали из списка, а после повторного входа появлялись снова (короткий список сразу догружал всё). `keepLoadedHistory()` в `src/stores/sessions.ts` сохраняет сообщения старше полученной страницы, если полная история уже известна; сохраняются только сообщения строго старше первого в странице, чтобы revert-очистка на сервере не воскрешала удалённые.
- **Кнопка «стоп» больше не пропадает.** Она показывалась только по локальному флагу `sending`, поэтому запуск, начатый не с этого экрана (открыли посреди выполнения, приложение перезапустилось, SSE переподключился) нечем было прервать — например, долгую сборку APK. Теперь `canStop = isSending || sessionBusy` (статус сервера), а отказ сервера показывает алерт вместо тихой записи в `error`. `abortSession()` возвращает `boolean`.
- **Кнопка вложения больше не «мертвая».** `launchImageLibraryAsync` и чтение буфера обмена могли падать необработанным промисом — кнопка не делала ничего и молчала. Оба пути обёрнуты в try/catch с алертом, пикер закрывает клавиатуру и игнорирует повторный запуск, пока открыт.
- **Список сессий больше не обрезан 50.** `GET /api/session` по умолчанию отдаёт 50 новейших, а транспорт не читал `cursor.next`, поэтому старые сессии, видимые в TUI, отсутствовали в приложении (upstream #188, #182). Транспорт V2 идёт по курсору (до 4 страниц по 200), список показывает до 800 корневых сессий. V1-сервер по умолчанию отдаёт 100 и обрезает молча — его `/experimental/session` тоже опрашивается постранично по заголовку `x-next-cursor` (повторный/битый курсор завершает обход, чтобы не зациклиться).
- Тесты: `composer-taps.regression.test.ts`, расширены `message-page` (keepLoadedHistory), `sdk.integration` и `sdk-v1.integration` (курсоры сессий).

### Любимые модели и карточки инструментов (та же ветка)

- **Любимые модели в пикере.** Звёздочка в строке модели (оба пикера: в сессии и в «Новой сессии»), секция «Любимые» сверху. Хранится как `[[scope, keys]]` в `opencode_model_favorites_v1` через тот же контроллер, что и скрытые модели (`createModelVisibility` получил параметр ключа). Любимая модель остаётся и в списке своего провайдера, скрытая модель в любимые не попадает. Сортировка «выбранное сверху» секцию не сдвигает.
- **Карточка инструмента больше не бывает пустой.** Три причины, все исправлены: (1) `session.tool.progress` присылает текст о том, что делает инструмент, только в `metadata.title`, а `toolPartUpdated()` его принимал и выбрасывал — долгий запуск выглядел как голое имя; (2) `session.tool.success` с пустым выводом давал `output: ""`, и развёрнутая карточка рендерила пустоту вместо входных данных; (3) сервер 2.x называет терминал `shell`, а распознавался только `bash` — не было ни иконки терминала, ни команды. Логика вынесена в `src/lib/tool-view.ts` (`toolTitle`, `toolDetailText`, `toolCommand`, `isShellTool`), карточка берёт её оттуда; пустой вход (`input.started` присылает `{}`) больше не даёт стрелку, открывающую пустоту.
- Тесты: `tool-view.test.ts` (5), `tool-call-card.regression.test.ts` (2), расширены `model-picker-filter` (+4), `model-visibility` (+1), `v2-compat` (+1). Итог: 642 теста, покрытие 98.37% строк / 86.01% ветвей.

Что нового в 0.2.25:

- **Композер больше не уезжает под клавиатуру.** Причина была в том, что RN-события клавиатуры в этом приложении не приходят вообще: под bridgeless-архитектурой `ReactSurfaceView` не ставит `ReactInstanceManager`, поэтому слушатель `ReactRootView.onGlobalLayout` выходит раньше отправки `keyboardDidShow`. Подробности: `docs/run-resync-validation.md`, `docs/security-review-0.2.21.md`, `docs/connection-status-validation.md`, `docs/model-visibility-validation.md`, пользовательское описание — `README.md` (en) и `README.ru.md` (ru).

## Как собрать и выпустить

Тестовый APK без релиза: запушить коммиты → `Build Android APK` (workflow_dispatch, `reuse_apk_run_id` пустой) → артефакт `app-release`. Release и тег не создавать.

Релиз:
1. Поднять версию в четырёх местах: `package.json`, `app.json` (`expo.version` + `expo.android.versionCode`), `android/app/build.gradle` (`versionName` + `versionCode`), и проверки `versionCode='NN'` / `versionName='x.y.z'` в `.github/workflows/build.yml`.
2. `npm run check:versions` — версии в трёх файлах должны совпасть.
3. Слить в `main`, поставить тег `vX.Y.Z`, дождаться зелёного CI на теге.
4. Опубликовать GitHub Release вручную с текстом изменений в описании и приложить `app-release.apk` под именем `opencode-mobile-v2.apk` (+ `SHA256SUMS.txt`): workflow Release не создаёт, а `releases/latest/download/opencode-mobile-v2.apk` используется встроенной проверкой обновлений. **Описание релиза — на двух языках: сначала английский, потом русский** (разделы `English` / `Русский`).
5. Обновить `README.md` (английский, основной) и `README.ru.md` (русский), затем этот файл.

## Правила окружения этого форка

- Git в `E:/ai/opencode-mobile` требует разового `git -c safe.directory=E:/ai/opencode-mobile ...`.
- `gh` CLI не авторизован: работать через `git credential fill` → токен → REST API (dispatch, artifacts, merge, releases, uploads.github.com).
- UTF-8 JSON для REST собирать в `node` и отправлять `Invoke-RestMethod -InFile`; PowerShell `ConvertTo-Json` ломает кириллицу.
- Перед подтверждением «готово» прогонять `npm run check:versions`, `npm run typecheck`, `npm run test:coverage`.
- `dist/` — локальные APK прошлых сборок, untracked; в Git не добавлять.
