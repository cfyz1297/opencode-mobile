# OpenCode Mobile — мастер-документ (форк cfyz1297)

Актуально на **2026-11-06**.

- App: **`cc.agentlabs.opencode`** — Expo/React Native Android-клиент к собственному серверу `opencode serve`. Работает с **обоими поколениями API**: V2 (`/api/*`, opencode 2.x) и V1 (`/session`, `/global/event`, opencode 1.18.x); версия определяется автоматически, в настройках можно включить принудительно.
- Репозиторий форка: **`cfyz1297/opencode-v1-v2-mobile`**. Апстрим для справки: `dzianisv/opencode-mobile`.
- Пользователь запускает сервер в Termux на телефоне; приложение — клиент к нему.
- **Текст релиза пишется на двух языках: сначала английский, потом русский.** Правило действует с 0.2.30, распространяется на описание GitHub Release, `README.md`/`README.ru.md` и этот файл.

## Что вошло в 0.3.1 (2026-11-06)

- **Краш при выходе из сессии во время стрима.** Экран сессии перерисовывается на каждой порции SSE, а опции заголовка задавались инлайново через `<Stack.Screen options={{…}}>`. Каждая перерисовка заново отправляла конфигурацию нативного хедера; выход из экрана посреди прогона разбирал его одновременно с этим обновлением, и `react-native-screens` падал с «child already has a parent» (апстрим Sentry `OPENCODE-MOBILE-6/-7`, исправлено в v0.4.17 коммитом `0bbfa70`). Теперь опции применяются через `navigation.setOptions` в `useEffect`; в зависимостях только видимые данные заголовка, включая `contextPercent`, поэтому кольцо контекста продолжает обновляться, но не на каждый чанк.
- **Регрессия закреплена** `src/lib/session-header.regression.test.ts` (3 теста): запрещает `<Stack.Screen` на экране сессии, проверяет `setOptions`, сохранение title/headerRight и полный список зависимостей.
- **GitHub Pages снова публикуется.** После переименования репозитория деплой `gh-pages` 2026-11-04 завис в `updating_pages` и через 10 минут упал по таймауту (`deploy-pages`, «Timeout reached, aborting!»); Pages остался в статусе `errored`, сайт отдавал 404. Причина — зависшая сборка на стороне Pages, а не содержимое ветки: та же ветка у апстрима собирается за ~32 с. `POST /repos/{owner}/{repo}/pages/builds` пересобрал сайт за 57 с, статус `built`, последний deployment — `success`. Если повторится: тот же POST, при упорном зависании — выключить и снова включить Pages в Settings → Pages.

## Что вошло в 0.3.0 (ветка `feat/server-api-v1`, 2026-11-04)

- **Совместимость с opencode 1.x (V1 API).** Новый транспорт `src/lib/sdk-v1.ts` (порт upstream PR #209 / релиза v0.4.16): `/session`, `/experimental/session`, `/session/{id}/prompt_async`, `/global/event`, `/permission/*`, `/question/*`, `/file*`, `/path`, `/agent`, `/command`, `/provider`, `/config`. Модель/агент в V1 едут в теле промпта — отдельных `POST /session/{id}/model|agent` там нет. Ответы V1 отдаются в той же форме, что и адаптированные V2, поэтому сторы и экраны не менялись. События `session.idle`, `permission.updated` и `permission.v2.*` (их шлёт сервер 1.18.x) нормализуются в те имена, которые уже знает `src/stores/events.ts`.
- **Определение версии сервера.** `src/lib/api-detect.ts`: `GET /api/info` (JSON или 401/403 → V2), иначе `GET /global/health` (JSON или 401/403 → V1); HTML на обоих маршрутах = это не сервер opencode. Решение принимается по типу ответа, а не по коду, потому что неизвестный маршрут на обоих поколениях отдаёт `200 text/html` из веб-интерфейса. Результат пишется в подключение (`api`, `serverVersion`) и сбрасывается при смене URL; ошибка пробы оставляет прежнее поведение (V2), чтобы сохранённое подключение не переставало открываться.
- **Переключатель «Настройки → Сервер → API сервера»** (`auto` / `v1` / `v2`). `auto` — определение и запоминание; принудительное значение обходит пробу и применяется сразу (клиент и SSE пересоздаются), чтобы можно было обойти проблему сервера. Настройка хранится вместе с остальными (`settings.serverApi`), при загрузке неизвестное значение падает в `auto`.
- **Туннели.** Запросы несут `ngrok-skip-browser-warning` и `Bypass-Tunnel-Reminder` (upstream #219): иначе ngrok отдаёт свою страницу-заглушку вместо API, и приложение сообщало «неверный пароль».
- **Уведомления без серверного текста.** Запрос подтверждения и вопрос агента больше не выносят в шторку имя инструмента, пути, команду и текст вопроса (аудит upstream M-03): только фиксированные строки, детали — в приложении.
- **Диагностика.** Health-проба успешна только при JSON или 401/403 (`requireJson` + `chooseHealthProbe` в `src/lib/diagnostics.ts`, `diagnostics-classify.ts`), поэтому HTML-заглушка больше не читается как «соединение работает». В отчёт добавлена строка `Server API: v1|v2`.
- Тесты: `src/lib/api-detect.test.ts` (6), `src/lib/sdk-v1.integration.test.ts` (15, настоящий HTTP-сервер), плюс расширены `connection-bootstrap`, `diagnostics-classify`, `settings-persistence`, `headers`, `notify-format`.
- Отчёт безопасности: `docs/security-review-server-api.md`.

### Исправления по отчётам с устройства (та же ветка)

- **История чата больше не пропадает.** `loadOlderMessages()` выставляет `hasMore=false`, но каждое обновление экрана (фокус, возврат из фона, реконнект) заменяло переписку страницей, обрезанной до значения настройки, — сообщения исчезали из списка, а после повторного входа появлялись снова (короткий список сразу догружал всё). `keepLoadedHistory()` в `src/stores/sessions.ts` сохраняет сообщения старше полученной страницы, если полная история уже известна; сохраняются только сообщения строго старше первого в странице, чтобы revert-очистка на сервере не воскрешала удалённые.
- **Кнопка «стоп» больше не пропадает.** Она показывалась только по локальному флагу `sending`, поэтому запуск, начатый не с этого экрана (открыли посреди выполнения, приложение перезапустилось, SSE переподключился) нечем было прервать — например, долгую сборку APK. Теперь `canStop = isSending || sessionBusy` (статус сервера), а отказ сервера показывает алерт вместо тихой записи в `error`. `abortSession()` возвращает `boolean`.
- **Кнопка вложения больше не «мертвая».** `launchImageLibraryAsync` и чтение буфера обмена могли падать необработанным промисом — кнопка не делала ничего и молчала. Оба пути обёрнуты в try/catch с алертом, пикер закрывает клавиатуру и игнорирует повторный запуск, пока открыт.
- **Список сессий больше не обрезан 50.** `GET /api/session` по умолчанию отдаёт 50 новейших, а транспорт не читал `cursor.next`, поэтому старые сессии, видимые в TUI, отсутствовали в приложении (upstream #188, #182). Транспорт V2 идёт по курсору (до 4 страниц по 200), список показывает до 800 корневых сессий. V1-сервер по умолчанию отдаёт 100 и обрезает молча — его `/experimental/session` тоже опрашивается постранично по заголовку `x-next-cursor` (повторный/битый курсор завершает обход, чтобы не зациклиться).
- Тесты: `composer-taps.regression.test.ts`, расширены `message-page` (keepLoadedHistory), `sdk.integration` и `sdk-v1.integration` (курсоры сессий).

### Любимые модели и карточки инструментов (та же ветка)

- **Любимые модели в пикере.** Звёздочка в строке модели (оба пикера: в сессии и в «Новой сессии»), секция «Любимые» сверху. Хранится как `[[scope, keys]]` в `opencode_model_favorites_v1` через тот же контроллер, что и скрытые модели (`createModelVisibility` получил параметр ключа). Любимая модель остаётся и в списке своего провайдера, скрытая модель в любимые не попадает. Сортировка «выбранное сверху» секцию не сдвигает.
- **Карточка инструмента больше не бывает пустой.** Три причины, все исправлены: (1) `session.tool.progress` присылает текст о том, что делает инструмент, только в `metadata.title`, а `toolPartUpdated()` его принимал и выбрасывал — долгий запуск выглядел как голое имя; (2) `session.tool.success` с пустым выводом давал `output: ""`, и развёрнутая карточка рендерила пустоту вместо входных данных; (3) сервер 2.x называет терминал `shell`, а распознавался только `bash` — не было ни иконки терминала, ни команды. Логика вынесена в `src/lib/tool-view.ts` (`toolTitle`, `toolDetailText`, `toolCommand`, `isShellTool`), карточка берёт её оттуда; пустой вход (`input.started` присылает `{}`) больше не даёт стрелку, открывающую пустоту.
- Тесты: `tool-view.test.ts` (5), `tool-call-card.regression.test.ts` (2), расширены `model-picker-filter` (+4), `model-visibility` (+1), `v2-compat` (+1).

### Статистика сессии и объём истории (та же ветка)

- **Кольцо контекста в заголовке вместо иконки.** `src/components/chat/ContextRing.tsx` (`react-native-svg`, уже в зависимостях) рисует дугу, заполненную на процент занятого контекста, с цветом по уровню (синий → жёлтый после 50% → красный после 80%). Тап открывает панель. Пустое кольцо всё равно читается как кнопка (точка в центре).
- **Общая стоимость в панели.** Рядом с токенами и процентом: `· $0.0392`. Раньше стоимость считалась суммой по загруженным сообщениям, то есть занижалась для длинной сессии (страница — не вся сессия). Теперь предпочитается `session.cost` из `/api/session/{id}` (поле копится сервером), сумма по сообщениям осталась запасным вариантом. Обе цифры (кольцо и панель) считает один `computeSessionStats()` из `src/lib/session-stats.ts`, чтобы не разъезжались.
- **Настройка «Вся сессия».** `ALL_TURNS = 0` в `message-page.ts` — максимальное значение в списке `5 / 10 / 25 / 50 / Вся` (вкладка «Подключения», блок предпочтений). Для неё транспорт запрашивает транскрипт целиком (`client.session.allMessages()`), обрезка не применяется, `hasMore` остаётся `false`.
- **Найден и исправлен тихий лимит 50.** `loadOlderMessages()` вызывал `client.session.messages(id)` без `limit`, а сервер по умолчанию отдаёт 50 сообщений — и потом выставлял `hasMore=false`, после чего догрузить было нечем. Это и есть «не видно всех сообщений» из отчёта. Теперь запрос идёт с максимумом (200) и следует курсору, пока тот приносит новые строки (на текущей сборке сервера курсор сообщений отдаёт пустую страницу — обход на этом и завершается, страховка от зацикливания на пустом/повторном курсоре и 10 страницах).
- **Выбор уровня рассуждений при открытой клавиатуре.** Шторка `VariantPicker` не знала про IME и оставалась за клавиатурой — нижняя строка («High») была недоступна. Теперь чип закрывает клавиатуру перед открытием, а шторка получила `keyboardBehavior="interactive"` и `android_keyboardInputMode="adjustResize"`, как у выбора модели и папок.
- **Стоимость сессии на провайдере, который её не отдаёт.** `opencode-go` не присылает цену ни в сообщениях, ни в записи сессии, поэтому панель показывала «без затрат» весь прогон. Теперь шаги ценятся по каталогу модели (та же формула, что у футера пузыря — `estimateCost` из `message-run.ts`), а накопленные `session.tokens` ценятся по каталогу последней модели. Тест `session-stats.test.ts` (7).
- **Бейдж удаления вложения** больше не обрезается: он стоял в `-6` по верхнему/правому краю и обрезался `ScrollView`, теперь внутри миниатюры (`ImageAttachments.tsx`).
- Тесты: `session-stats.test.ts` (7), `session-info.regression.test.ts` (3), `variant-picker-keyboard.regression.test.ts` (2), `message-page` (+3 на ALL_TURNS), `sdk.integration` (+2 на `allMessages`), `sdk-v1.integration` (+1). Итог: 663 теста.

Что нового в 0.2.30:

- **Неудачный прогон показывает причину.** Сервер хранит причину падения в assistant-сообщении (`info.error`), а текста ответа у такого сообщения нет, поэтому `MessageBubble` рисовал пустой пузырь: сессия, которая на самом деле падала, выглядела зависшей и «переставшей отвечать». Наблюдаемый случай — бесплатная модель отвечала `429 Free usage limit reached`, и в приложении не появлялось ничего. Теперь причина выводится красным в пузыре, там же, где был бы ответ; данные берутся из переписки, поэтому строка остаётся и после перезахода в сессию. Если сервер не прислал текст, показывается ключ `chat.message.failed` (en/ru/zh-Hans). Тест — `src/components/chat/message-bubble-error.test.ts` (рендерит настоящий компонент с детерминированными адаптерами; без фикса красный).

Что нового в 0.2.29:

- **Уточнение можно отправить во время работы агента.** `handleSend` блокировался по `isSending` — флагу прогона, который SSE снимает только при переходе сессии в idle, поэтому до конца прогона отправка молча ничего не делала. Теперь блокируется только запрос в полёте (`sendInFlight`), сервер ставит следующий промпт в очередь. Тест — `src/lib/composer-and-questions.test.ts`.
- **Отвеченные вопросы остаются в диалоге.** Сервер удаляет форму по `question.replied`, и карточка исчезала, оставляя эхо на 2.5 с. Теперь ответ пишется в `answeredQuestions` (`src/lib/answered-questions.ts`, стор `src/stores/events.ts`), а `AnsweredQuestionCard` (`src/components/chat/AnsweredQuestion.tsx`) рисует карточку на месте вопроса: свёрнута в строку, по нажатию раскрывает варианты с отмеченными ответами. Хранится только в памяти (не персистится). Тесты — `src/lib/answered-questions.test.ts`.
- **«Сообщений на странице» → запросы.** Один промпт даёт десятки записей (шаг на вызов инструмента), поэтому 50 «сообщений» часто были одним обращением. `src/lib/message-page.ts`: `messageLimitForTurns` (20 сообщений на запрос, потолок API 200), `trimToTurns` (страница начинается с промпта пользователя), `hasMore` = страница обрезана; если один запрос не покрывает N обращений, `selectSession` дозагружает сессию целиком. Теперь подсказки (permissions, подтверждение ответа, вопросы) живут в `ScrollView` с `flexShrink: 1`: они прокручиваются в остатке места, композер всегда виден.

## Как собрать и выпустить

Тестовый APK без релиза: запушить коммиты → `Build Android APK` (workflow_dispatch, `reuse_apk_run_id` пустой) → артефакт `app-release`. Release и тег не создавать.

Релиз:
1. Поднять версию в трёх местах: `package.json`, `app.json` (`expo.version` + `expo.android.versionCode`), `android/app/build.gradle` (`versionName` + `versionCode`). Литералы в `.github/workflows/build.yml` не нужны: CI читает ожидаемые значения из `app.json`. При смене keystore обновить `EXPECTED_CERT` в том же шаге проверки.
2. `npm run check:versions` — версии в трёх файлах должны совпасть.
3. Слить в `main`, поставить тег `vX.Y.Z`, дождаться зелёного CI на теге.
4. Опубликовать GitHub Release вручную с текстом изменений в описании и приложить `app-release.apk` под именем `opencode-mobile-v2.apk` (+ `SHA256SUMS.txt`): workflow Release не создаёт, а `releases/latest/download/opencode-mobile-v2.apk` используется встроенной проверкой обновлений. **Описание релиза — на двух языках: сначала английский, потом русский** (разделы `English` / `Русский`).
5. Обновить `README.md` (английский, основной) и `README.ru.md` (русский), затем этот файл.

## Правила окружения этого форка

- Git в `E:/ai/opencode-mobile` требует разового `git -c safe.directory=E:/ai/opencode-mobile ...`.
- `gh` CLI не авторизован: работать через `git credential fill` → токен → REST API (dispatch, artifacts, merge, releases, uploads.github.com).
- UTF-8 JSON для REST собирать в `node` и отправлять `Invoke-RestMethod -InFile`; PowerShell `ConvertTo-Json` ломает кириллицу.
- Перед подтверждением «готово» прогонять `npm run check:versions`, `npm run typecheck`, `npm run test:coverage`.
- `dist/` — локальные APK прошлых сборок, untracked; в Git не добавлять.
