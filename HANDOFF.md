Значения 5/10/25/50, по умолчанию 10. `settingsVersion: 2` — старые значения в сообщениях несопоставимы, поэтому берётся дефолт (остальные настройки сохраняются). Тесты — `src/lib/message-page.test.ts`, `src/lib/settings-persistence.test.ts`.

Что нового в 0.2.28:

Цены каталога приходят в `ProviderModel.cost` (`src/stores/catalog.ts`, `src/lib/v2-compat.ts`) и подставляются в `app/session/[id].tsx`. Старые сессии, где сервер считал цену сам, дают ту же сумму. Тесты — `src/lib/message-run.test.ts`.

Теперь дельты склеиваются (`src/lib/part-batch.ts`, одна запись в стор на ~40 мс, вызов через `applyParts` в `src/stores/sessions.ts`), а поток уступает макрозадачу после каждого чанка (`src/lib/sdk.ts`). Тесты — `src/lib/part-batch.test.ts`.

Что нового в 0.2.25:

- **Композер больше не уезжает под клавиатуру.** Причина была в том, что RN-события клавиатуры в этом приложении не приходят вообще: под bridgeless-архитектурой `ReactSurfaceView` не ставит `ReactInstanceManager`, поэтому слушатель `ReactRootView.onGlobalLayout` выходит раньше отправки `keyboardDidShow`. Плюс edge-to-edge: окно под IME не сжимается. Решение двухслойное: `MainActivity` (`installImeReporter`) и сжимает корневую view под инсет клавиатуры (`updatePadding`), и отдаёт `imeInset` в JS для RN `Modal`; полноэкранные экраны своих отступов больше не добавляют.
- **Блок вопросов прокручивается.** Список сообщений схлопывается в ноль (`flex: 1`), поэтому карточка вопроса фиксированной высоты выталкивала композер за нижний край, и писать в чат при висящих вопросах было нельзя. Теперь подсказки (permissions, подтверждение ответа, вопросы) живут в `ScrollView` с `flexShrink: 1`: они прокручиваются в остатке места, композер всегда виден.
- Тесты: `src/lib/keyboard-inset.test.ts` — нормализация `imeInset`, контракт «нативный эмиттер ↔ JS-слушатель», запрет собственных отступов на полноэкранных экранах, и статическая проверка, что композер вне прокручиваемого блока подсказок (падает без фикса).

Что нового в 0.2.24:

- **Новая сессия создаётся в выбранном проекте, а не в `~` сервера.** V2 игнорирует `x-opencode-directory` на `POST /api/session`, поэтому любая папка из «недавних», списка проектов сервера, обзора папок или переключателя проекта превращалась в сессию в домашнем каталоге. Папка теперь едет в теле запроса (`location.directory`) — `src/lib/sdk.ts`; регрессия закреплена HTTP-тестом `src/lib/directory-client.test.ts` (падает без фикса).
- **Поле ввода не прячется за клавиатурой.** Высота клавиатуры считалась как `windowHeight - screenY`; при обязательном edge-to-edge (Expo SDK 54) видимая область по-прежнему исключает системные панели, поэтому отступ схлопывался до высоты панели навигации (~24dp) и композер оставался под клавиатурой. Теперь отступ = высота клавиатуры из события (`imeInsets.bottom - barInsets.bottom`) + нижний safe-area inset — `src/lib/keyboard-inset.ts` (`keyboardPadding`), общий для чата, новой сессии, подключений и мастера туннеля. Покрыто `src/lib/keyboard-inset.test.ts`.

Что нового в 0.2.23:

- **Сессия оживает после потери сети.** После разрыва и возврата сети сессия оставалась «мёртвой»: «Работаю…» навсегда, поле ввода заблокировано (`sending`), прошлая работа не видна. Исправление: `client.session.active()` (`GET /api/session/active`, есть с 2.0.24) в `src/lib/sdk.ts`; в `src/stores/events.ts` — active-список авторитетен и запрашивается параллельно с перепиской, догон перенесён в `onActivity`. Старый сервер без маршрута — прежняя эвристика. Отчёт: `docs/run-resync-validation.md`.

## Как собрать и выпустить

Тестовый APK без релиза: запушить коммиты → `Build Android APK` (workflow_dispatch, `reuse_apk_run_id` пустой) → артефакт `app-release`. Release и тег не создавать.

Релиз:
1. Поднять версию в четырёх местах: `package.json`, `app.json` (`expo.version` + `expo.android.versionCode`), `android/app/build.gradle` (`versionName` + `versionCode`), и проверки `versionCode='NN'` / `versionName='x.y.z'` в `.github/workflows/build.yml`.
2. `npm run check:versions` — версии в трёх файлах должны совпасть.
3. Слить в `main`, поставить тег `vX.Y.Z`, дождаться зелёного CI на теге.
4. Опубликовать GitHub Release вручную с текстом изменений в описании и приложить `app-release.apk` под именем `opencode-mobile-v2.apk` (+ `SHA256SUMS.txt`): workflow Release не создаёт, а `releases/latest/download/opencode-mobile-v2.apk` используется встроенной проверкой обновлений.
5. Обновить `README.md` (английский, основной) и `README.ru.md` (русский), затем этот файл.

## Правила окружения этого форка

- Git в `E:/ai/opencode-mobile` требует разового `git -c safe.directory=E:/ai/opencode-mobile ...`.
- `gh` CLI не авторизован: работать через `git credential fill` → токен → REST API (dispatch, artifacts, merge, releases, uploads.github.com).
- UTF-8 JSON для REST собирать в `node` и отправлять `Invoke-RestMethod -InFile`; PowerShell `ConvertTo-Json` ломает кириллицу.
- Перед подтверждением «готово» прогонять `npm run check:versions`, `npm run typecheck`, `npm run test:coverage`.
- `dist/` — локальные APK прошлых сборок, untracked; в Git не добавлять.
